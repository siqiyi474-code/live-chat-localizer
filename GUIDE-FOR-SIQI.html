Live Chat Localizer: your guide

For Siqi. No programming needed. About 1 to 2 hours in total.

The idea in one sentence: the demo is already built. Your job is to make the localization decisions yours (the examples, the glossary, the rules), because that is what TikTok will judge and ask you about.

Your to-do list (before sending)

  1. ☐ Open the demo and play with it for 10 minutes (sections 1–2).
  2. ☐ Review the 20 comments, the rules and the glossary; change anything you wouldn't defend (sections 4–5). ~45 min.
  3. ☐ Pick your 4–6 best examples and fill in the case study in your own words. ~30 min.
  4. ☐ Tell Mario you're done, so he regenerates the single file and the screenshots (section 6).
  5. ☐ Put the case study as piece 01 of your portfolio PDF, with screenshots and the demo link.
  6. ☐ After sending: one hour with Mario making one change yourself, and practise the 2-minute walkthrough (section 7).

4. How to edit safely

Which program to use

  • Best: Visual Studio Code (free). Open the file with it: right-click → "Open with" → VS Code. It colours the text, so mistakes are easy to see.
  • Windows, no install: Notepad works.
  • Avoid Word, WPS or Mac TextEdit: they change the quote marks and break the file.

The one rule: change only what is between the quotes

Every entry looks like this:

{ id: 6, user: "chris_eats", lang: "en", text: "what does it actually smell like? no cap", tone: "question",
  out: {
    zh: { literal: "它实际上闻起来像什么？没有帽子", localized: "说真的，到底是什么味儿？" },
    ...
  note: "'no cap' becomes 'no hat' in MT; it means 'for real'...",

You can change the text inside "…". Leave everything else exactly as it is: the words before the colon (localized:), the quotes, commas, { } and [ ].

OKlocalized: "说真的，这到底啥味儿？"
Breakslocalized: "说真的，这到底啥味儿？ (closing quote deleted)
Breaksnote: "it means "for real"" (straight quotes inside the text)
Fixnote: "it means 'for real'" or use Chinese quotes “for real” or 「for real」 inside

Chinese punctuation (，。！？) and emoji inside the quotes are fine.

Check every change

  1. Save the file (Ctrl+S, or Cmd+S on Mac).
  2. Go back to the browser tab with the demo and reload (F5, or Cmd+R on Mac).
  3. If the chat plays normally, your change is good. Save and reload after every few edits, not once at the end, so you always know which edit caused a problem.

Common changes

  • Change a translation: edit the text after literal: or localized:.
  • Change your reason: edit note:. Keep it to one sentence, in English.
  • Change a tone tag: tone: must be one of: hype, affection, joke, greeting, question, request, negative, toxic.
  • Remove a comment you don't like: easiest is to ask Mario. Deleting a whole block by hand often leaves a bracket behind.
  • Add a new comment: copy a whole block from { id: down to its closing },, paste it right after, give it a new number in id, then change the texts.
  • Glossary: in localization.js, each term is one block { term: "666", … why: "…" },. Same rules.

5. What to review (the important part)

Everything in siqi/ is a draft written by Claude. Only keep what you would defend in an interview as your own decision.
  1. The 20 comments (stream-script.js). For each one ask: would a real viewer write this? Is the "localized" version natural? Is the "why" correct and is it how you would explain it?
  2. Spanish. Check it most carefully, or ask Mario: it's the language interviewers are least likely to test, but a mistake there would hurt.
  3. The 8 rules (top of localization.js). Do you agree? Rewrite them in your own words, and add one from your translation studies if you have it (a theory or a name you can cite gives you an edge over computer-science candidates).
  4. The glossary. Remove terms you wouldn't use; add slang you know is better.
  5. Choose your 4–6 best examples for the case study.

6. Sending it

7. In the interview

Be clear about who did what

Suggested line: "I designed the concept, the localization rules, the glossary and all the copy, and I built the prototype with Claude Code." The job post explicitly asks for AI-assisted development (Vibe coding), so this is a strength, not something to hide. Do not say you wrote the code by hand.

Before the interview, sit with Mario for an hour and make one change yourself (for example, add a new comment), so you can say how it works and show it live if asked.

A 2-minute demo walkthrough

  1. Problem (20 s): "A stream from Changsha has viewers from China, the US and Latin America. Machine translation makes chat readable but not understandable."
  2. Show it (40 s): switch to Machine literal and click the "no cap" comment: 没有帽子. Switch back to Localized: 说真的. Then show 666 → "LET'S GOOO".
  3. Your principle (20 s): "Chat slang is an action: cheering, teasing, asking. I translate what the viewer is doing, not the words." Point at the "Why" box.
  4. For the host (20 s): open the Reply queue: questions and purchase requests surface with a reply in the viewer's language.
  5. Product detail (20 s): open UI strings check: "Unirse al club de fans" doesn't fit the button, so it falls back to "Club de fans".

Questions to prepare

  • Why not just use machine translation? (Your answer: the literal/localized contrast.)
  • How would you scale this to 20 languages? (Rules + glossary feed the AI prompt; humans review the glossary per market.)
  • Why keep rude comments rude? (Rule R3: translators shouldn't censor; moderation decides.)
  • What would you add next? (For example Arabic, to test right-to-left layout.)

8. If something breaks

  • The page is empty or the chat doesn't start after an edit: a quote or comma is missing in the last thing you changed. Press Ctrl+Z (Cmd+Z) in the editor until it looks like before, save, reload.
  • VS Code shows a red wavy line: the mistake is on that line or just before it.
  • Still stuck: send Mario the file. Don't worry: the original is saved, nothing is lost.
